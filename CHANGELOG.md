# Changelog

All notable changes to `@polyant-ai/plugin-sdk` are recorded here. The format
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the package
follows [Semantic Versioning](https://semver.org/): the SDK version is the
compatibility contract between a plugin and the engine.

Consumers reference a release by its git tag:
`git+https://github.com/polyant-ai/polyant-sdk.git#vX.Y.Z`.

## [Unreleased]

### Changed

- The README documents the `system` block of `plugin.json`, which image-baked
  plugins use to ask the engine image for packages and environment variables, and
  says that marketplace bundles cannot carry it. Its examples use a neutral
  plugin name.

## [1.9.0] - 2026-10-02

### Added

- `ctx.artifacts` on `ToolContext`: a short-lived, one-shot, conversation-bound
  handoff of generated bytes between tools (`put` returns a handle, `take`
  consumes it). Exported types `ArtifactApi` and `ArtifactPayload`. The member is
  always present on the type, so a hand-built test context has to provide it.
- Dev mode bridges `ctx.artifacts` to the engine, and refuses locally an artifact
  that would not fit in one dev frame.

### Documentation

- `plugin.json` display fields (`displayName`, `description`), parameter labels,
  and the marketplace fields (`longDescription`, `icon`, `category`, `publisher`,
  `documentationUrl`) with how publication works.

## [1.8.0] - 2026-09-15

### Added

- Dev mode serves hook functions: `serveDevSession` accepts `hooks` beside
  `tools`, with `loadHooksFromPaths`, `devHook` (`overrides` an existing function
  or `bindTo` an event for the session) and `createHookCtxProxy`.

### Changed

- Development dependency vitest moved from 3.x to 4.1.11.

## [1.7.0] - 2026-09-09

### Added

- `ctx.knowledge`: read, write and manage access to the agent's own knowledge
  base, present only when the agent grants it, with the read/mutation failure
  contract (reads reject, mutations answer `{ ok: false, reason }`).
- `requiredKnowledge` on `defineTool`, so the engine does not equip a tool on an
  agent that grants less than it needs.
- The `limit_reached` knowledge denial reason.

## [1.6.0] - 2026-09-04

### Added

- The `@polyant-ai/plugin-sdk/dev` entry point: the client runtime that connects
  local tool files to a remote agent over the engine's dev bridge
  (`serveDevSession`, `loadToolsFromPaths`, the wire protocol and its types).

### Fixed

- A dev session confirms `tools.update` before adopting the new tool set.
- A pending reconnection keeps the event loop alive until the session is closed.

## [1.5.0] - 2026-07-29

### Added

- `halt.persist` on the hook result: `persist: false` makes a halted turn
  ephemeral, with no message rows, trace, state flush or summary work.

## [1.4.0] - 2026-07-24

### Added

- The `regenerate` hook control return, which replays the whole turn, and
  `regenerationCount` on the `response_generated` payload.

## [1.3.0] - 2026-07-23

### Added

- `ctx.oauth` on `ToolContext` and the `oauthRequiredSecrets` helper.
- The `OAuthProviderSpec` type for OAuth providers a plugin declares in
  `plugin.json`.

### Documentation

- Least-privilege secret scoping in the tool and hook contexts.

## [1.2.0] - 2026-07-06

### Added

- `defineHook` and the hook-function contract (`HookSpec`,
  `HookFunctionDefinition`, `HookContext`, `HookResult`, `HookEvent`). A hook's
  `requiredSecrets` are validated at module load, as a tool's are.

## [1.1.0] - 2026-07-06

### Added

- Read-only conversation history on `ToolContext` (`ctx.conversation`).

## [1.0.0] - 2026-07-02

### Added

- First release: `defineTool`, `toJsonSchema`, the `requiredSecrets` contract
  with `normalizeRequiredSecrets` and `requiredSecretKeys`, and the stateless
  tool-authoring types, under the Apache-2.0 licence.
